# 智慧议会

针对真实用户困境的历史智慧决策系统。

很多问题不是缺信息，而是缺判断。

- 我该不该离婚
- 我该不该辞职创业
- 我的合伙人越来越不可靠
- 我知道该做什么，却一直拖延
- 我太在意别人的看法

这些问题往往没有标准答案，但又必须做决定。

`智慧议会` 想做的事很简单：

把一个人的困境，变成一场真正的思想碰撞，最后收敛成一个可以执行的决定。

它不是“十个古人轮流说话”的角色扮演，而是一个帮助人做决定的思考系统。

## 怎么使用这个 Skill

最直接的用法，是在支持 Skill 的代理里显式调用 `$wisdom-council`，然后直接描述你的真实困境。

### 最小用法

```text
用 $wisdom-council 帮我判断：我该不该辞职创业？
```

### 更好的提问方式

如果你愿意多给一点上下文，系统会更容易判题和选人。建议补充：

- 你现在在什么处境
- 你有哪些现实选项
- 你最担心失去什么
- 你最不能接受的结果是什么
- 这个决定的时间窗口有多长

例如：

```text
用 $wisdom-council 帮我判断：
我正在考虑 3 个月内辞职创业。
现在有稳定收入，也有家庭责任。
我最怕失败后现金流断掉，但也怕继续拖下去错过窗口。
请重点看：风险、长期机会、家庭责任。
```

### 适合的追问方式

第一轮结束后，可以继续这样追问：

- 基于上一轮，只保留 3 位最关键的视角继续深挖
- 基于上一轮，重点比较“稳定 vs 自由”这条分歧
- 重新选 10 位，但这次优先创业、风险和组织视角
- 把最终裁决改成更保守 / 更激进的行动方案

### 适合的问题类型

- 关系、婚姻、家庭、亲子
- 职业选择、转行、创业、竞争
- 焦虑、意义感、虚无感、拖延
- 价值冲突、原则选择、边界判断
- 失败、低谷、重建、死亡与有限性

## Workflow

```text
User Question
  -> Router
  -> Retriever
  -> Council Builder
  -> Renderer
  -> Synthesizer
  -> Quality Checker
  -> Final Decision
```

简单理解：

```text
用户问题
  -> 分析问题结构
  -> 选择合适智慧视角
  -> 构建十人议会
  -> 生成多角度讨论
  -> 综合判断
  -> 输出行动方案
```

## 系统做什么

- 先识别问题的领域、冲突类型、情绪状态、隐藏动机和真正阻碍点
- 再从智慧库里动态挑选最合适的十种思想视角
- 让这些视角围绕同一个问题产生分歧
- 最后把分歧收敛成判断、代价和行动

## 用户会得到什么

每个回答都会包含：

- 问题重述
- 为什么选择这十个视角
- 十个不同判断角度
- 主要共识
- 关键分歧
- 最终裁决
- 24 小时行动
- 7 天行动计划
- 下一轮深化问题

目标不是提供更多观点，而是帮助用户做出决定。

## 一个简化示例

用户问题：

> 我该不该辞职创业？

系统可能输出：

- 主要共识：如果没有验证需求，现在辞职风险过高
- 关键分歧：应该立刻全职投入，还是先做副业验证
- 最终裁决：先建立副业验证，而不是直接辞职
- 24 小时行动：联系三个潜在客户验证需求
- 7 天计划：完成第一轮用户访谈和产品原型

## 为什么要做这个 skill

很多“智慧顾问”类提示词会失败，因为：

- 每次都是同一批人物
- 看起来有很多观点，但没有真正冲突
- 最后只剩一段好听的鼓励

这个系统的目标是：

让不同智慧真正发生碰撞，然后给出一个可以执行的判断。

## 边界

系统不会：

- 编造历史名言
- 把明显伤害关系包装成修复关系
- 把法律、医疗、税务或投资问题当作纯智慧问题
- 以抽象鼓励作为结尾
